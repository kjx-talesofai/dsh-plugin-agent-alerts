# Phase 0 探针 — round 3

**刷新页面（⌘R）** 后面板会变成新的一组按钮。

## 已经排除的

round 2 四个按钮**每一次都报 `onshow ✓`，但一条横幅都没出现**。所以：

- ❌ 不是 JS 引用被回收（B 组专门持了引用）
- ❌ 不是 macOS 去重（C 组正文每次不同）
- ❌ 不是"关掉上一条"的问题（D 组）
- ❌ 不是签名问题 —— `codesign --verify --strict` 通过，是有效的 Developer ID 签名

我查了 Electron 42 的破坏性变更：macOS 通知改走 `UNNotification` API，
**未签名的 app 会静默失败**（只发 `failed` 事件）。DSH 是签过名的，所以理论上不该中招 ——
而且你的 `com.deepseek.dsh` 在 macOS 的通知中心数据库里**根本不存在**
（另外 130 个 app 都在）。这两件事凑在一起只有两种解释。

## 这一轮的四个按钮

前三轮我把 `silent: true` **一直固定着**。现在没有别的变量可怪了，它成了头号嫌疑。
另外"窗口在前台"也可能是一个因素 —— 你点按钮的时候窗口当然是前台的。

| 按钮 | 改了什么 | 怎么点 |
| --- | --- | --- |
| **A 立刻 · 有声** | `silent:false` | 点一下，马上看有没有横幅 |
| **B 5 秒后 · 有声** | 加了 5 秒延迟 | **点完立刻 ⌘Tab 切到别的 app**，然后看 |
| **C 5 秒后 · 无声** | 延迟 + `silent:true` | 同上；和 B 对比就知道 `silent` 有没有影响 |
| **D 连响 3 次 · 有声** | 延迟 + 连响 3 次（每 5 秒） | 点完切走，慢慢观察 |

面板顶部会出现黄色倒计时「⏳ 4.3 秒后响：… —— 现在切走」，照着做就行。

**请告诉我：A / B / C / D 各自有没有出现横幅。** 只要 B 或 D 在窗口后台时出现了，
方案就成立 —— 这个插件本来就是给"我不在看它"的时候用的。
